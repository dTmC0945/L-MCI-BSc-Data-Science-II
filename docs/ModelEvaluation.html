2.5 Model Evaluation

Let’s write a function to evaluate the model. It takes the model and a DataLoader for the dataset that we want to evaluate the model on, as well as a function to compute the metric for a given batch, and lastly a function to aggregate the batch metrics: [79] By default, it just computes the mean. 



def evaluate(model, data_loader, metric_fn, aggregate_fn=torch.mean): 
    model.eval() 
    metrics = [] 
    with torch.no_grad(): 
        for X_batch, y_batch in data_loader: 
            X_batch, y_batch = X_batch.to(device), y_batch.to(device) 
            y_pred = model(X_batch) 
            metric = metric_fn(y_pred, y_batch) 
            metrics.append(metric) 
    return aggregate_fn(torch.stack(metrics))

Now let’s build a TensorDataset and a DataLoader for our validation set, and pass it to our evaluate() function to compute the validation MSEMean Square ErrorMean Square Error: 



valid_dataset = TensorDataset(X_valid, y_valid) 
valid_loader = DataLoader(valid_dataset, batch_size=32) 
valid_mse = evaluate(model, valid_loader, mse) 
valid_mse

It works fine. But now suppose we want to use the RMSERoot-Mean Square ErrorRoot-Mean Square Error instead of the MSEMean Square ErrorMean Square Error. PyTorch does not have a built-in function for that, but it’s easy enough to write: 



def rmse(y_pred, y_true): 
    return ((y_pred - y_true) ** 2).mean().sqrt() 
 
evaluate(model, valid_loader, rmse)

The RMSERoot-Mean Square ErrorRoot-Mean Square Error should be equal to the square root of the MSEMean Square ErrorMean Square Error. However, when we compute the square root of the MSEMean Square ErrorMean Square Error that we found earlier, we get a different result: 



valid_mse.sqrt()

The reason is that instead of calculating the RMSERoot-Mean Square ErrorRoot-Mean Square Error over the whole validation set, we computed it over each batch and then computed the mean of all these batch RMSERoot-Mean Square ErrorRoot-Mean Square Errors.

That’s NOT mathematically equivalent to computing the RMSERoot-Mean Square ErrorRoot-Mean Square Error over the whole validation set.

To solve this, we can use the MSEMean Square ErrorMean Square Error as our metric_fn, and use the aggregate_fn to compute the square root of the mean MSE: [80] The mean of the batch MSEMean Square ErrorMean Square Errors is equal to the overall MSEMean Square ErrorMean Square Error since all batches have the same size. Well, except the last batch, which is often smaller, but this makes very little difference. 



evaluate(model, valid_loader, mse, 
         aggregate_fn=lambda metrics: torch.sqrt(torch.mean(metrics)))

Rather than implement metrics yourself, you may prefer to use the TorchMetrics library, [81] made by the same team as PyTorch Lightning. which provides many well-tested streaming metrics.

A streaming metric is an object that keeps track of a given metric, and can be updated one batch at a time. 



import torchmetrics 
 
def evaluate_tm(model, data_loader, metric): 
    model.eval() 
    metric.reset()  # reset the metric at the beginning 
    with torch.no_grad(): 
        for X_batch, y_batch in data_loader: 
            X_batch, y_batch = X_batch.to(device), y_batch.to(device) 
            y_pred = model(X_batch) 
            metric.update(y_pred, y_batch)  # update it at each iteration 
    return metric.compute()  # compute the final result at the end

Then we can create an RMSERoot-Mean Square ErrorRoot-Mean Square Error streaming metric, move it to the GPUGraphical Processing UnitA specialized electronic chip designed to rapidly render images, video, and 3D animations. Unlike a central processing unit (CPU) that processes tasks sequentially, a GPU uses parallel processing with thousands of smaller cores to handle many calculations at the same time., and use it to evaluate the validation set: 



rmse = torchmetrics.MeanSquaredError(squared=False).to(device) 
evaluate_tm(model, valid_loader, rmse)

If the performance on the training set is much better than on the validation set, your model is probably overfitting the training set, or there is a bug, such as a data mismatch between the training set and the validation set.
